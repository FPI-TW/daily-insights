# 專案審查基準（2026-09-02）

本文件是 2026-09-02 對 `main`（`dbf044a`）進行全面審查的結果，作為日後修復的
參考基準。每項發現都有穩定編號與狀態欄；修復時請直接更新狀態欄並附上 commit
或 PR，不要刪除項目。新的審查請另建檔案，不要覆寫本文件。

狀態定義：

| 狀態          | 意義                                        |
| ------------- | ------------------------------------------- |
| `open`        | 尚未處理                                    |
| `in-progress` | 已有分支或 PR 處理中                        |
| `done`        | 已合併至 `main`，備註欄記錄 commit 或 PR    |

| `external`    | 需要在 GitHub、AWS 或 Cloudflare 上手動設定 |

## 整體評估

工程基礎扎實：模組化單體、fail-closed 設定驗證、digest 固定的映像、離線契約
測試、完整的 session／CSRF／SSRF 防護。主要弱點在流程與治理：`main` 沒有分支
保護、production 環境沒有審核者、Playwright 從未在 CI 執行、ESLint 實際上沒有
規則，以及文件落後程式碼一到兩個迭代。審查當下 `main` 的 CD 已連續兩次失敗，
正式環境凍結在 `78c1abc`。

## 建議處理順序

1. 解除 CD 封鎖並決定新聞排程器去留（D-01、D-02）。
2. 加上 `main` ruleset 與 production 環境審核者（D-03、G-07）。
3. 設定日誌 handler 與 API 容器 tmpfs 容量（B-01、B-02）。
4. 移除或標示台股示範資料（F-01）。
5. 修正並將 Playwright 納入 CI，補上真正的 ESLint 規則（D-04、F-02、F-11）。
6. 文件同步：路線圖狀態、go-live 紀錄、語言一致性（G-03、G-04、G-05）。
7. 其餘技術債依嚴重度排程。
